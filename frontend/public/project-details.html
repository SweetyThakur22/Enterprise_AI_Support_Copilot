01 · Problem Statement

Production incidents cost thousands of dollars per minute

When a critical incident fires at 2 AM, engineers face a fragmented workflow: switching between dashboards, digging through thousands of log lines, searching Confluence for relevant runbooks, and making high-stakes remediation decisions under time pressure — all without structured AI assistance.

The gap: Monitoring tells you a service is unhealthy. It doesn't tell you why, what caused it, what the historical precedent is, or whether the proposed fix is safe to execute. Engineers carry all of that in their heads — or waste 30–60 minutes reconstructing it from scratch every incident.

02 · What the Product Does

AI-powered investigation in under 60 seconds

The platform automates the evidence-gathering and root-cause reasoning that engineers do manually. When an incident is selected, the system fetches the associated logs, parses the error timeline, retrieves semantically relevant knowledge-base documentation, identifies similar past incidents, and sends a structured evidence package to a large language model for analysis.

The LLM returns a validated JSON response: root cause, confidence score (0–100), confirmed facts, inferred assumptions, contradicting evidence (transparency feature), a timeline, and risk-scored remediation recommendations. High-risk recommendations require human approval before being executed. Every action is written to an immutable audit log.

03 · Key Features

Capabilities at a glance

Log Parsing Engine

Detects format (Oracle, syslog, JSON, Apache), extracts ORA-XXXXX / HTTP 5xx / timeout codes, builds a timestamped event timeline, and identifies the triggering event.

RAG Knowledge Retrieval

Six enterprise knowledge-base documents embedded with sentence-transformers (all-MiniLM-L6-v2, 384-dim) stored in pgvector. Top-5 semantically similar chunks retrieved per investigation.

Historical Incident Search

Finds similar past resolved incidents by error code match + semantic similarity. Returns top-3 with root cause and resolution hints to inform LLM reasoning.

LLM Analysis with Pydantic Validation

Claude (claude-sonnet-4-6) or Groq (OpenAI-compatible). Structured JSON output validated by Pydantic. Contradicting evidence and confidence bounds enforced. Prompt injection defence built in.

Approval Workflow

HIGH / CRITICAL risk recommendations require Incident Manager approval. Simulated action result recorded. Full approval history and comment trail persisted.

RBAC + Audit Trail

Four roles: Viewer, Support Engineer, Incident Manager, Admin. Every login, analysis trigger, and approval decision is written to an immutable audit log with IP, user, and timestamp.
